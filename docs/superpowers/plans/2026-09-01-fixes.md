## 1. Нижние панели наезжают друг на друга

**Симптом** (скрин от пользователя): панель «Твой заказ» лежит поверх таб-бара, кнопка обрезана, последние позиции списка не достать.

**Причина:** `.tb-sticky` (ui.css:569) и `.tb-tabbar` (ui.css:603) обе `position: fixed; bottom: 0` — стоят друг на друге. `.tb-page` (ui.css:11) даёт снизу всего 96px.

**Файлы:** `mini-app/src/ui/ui.css`, `mini-app/src/ui/tokens.css`

- Токены: `--tb-tabbar-h: 56px`, `--tb-sticky-h: 72px`.
- `.tb-tabbar`: `bottom: 0`, высота = `--tb-tabbar-h` + safe-area.
- `.tb-sticky`: `bottom: calc(var(--tb-tabbar-h) + var(--tb-safe-bottom))`, safe-area убрать (её держит таб-бар).
- `.tb-page`: `padding-bottom: calc(var(--tb-tabbar-h) + var(--tb-sticky-h) + var(--tb-safe-bottom) + var(--tb-space-lg))`.
- Проверить в браузере замером, как со шторкой: последний элемент списка должен быть доступен прокруткой.

## 2. Локальный запуск без Telegram

**Зачем:** быстрее дебажить, не поднимая туннель.

**Сервер** — `server/src/config.ts`, `server/src/api/middleware/authenticate.ts`, `server/src/index.ts`:
- `DEV_NO_TELEGRAM=true` в конфиг (`devNoTelegram: boolean`). Только для локалки.
- В `createAuthenticate`: если флаг включён — не проверять подпись и членство в чате, брать личность из заголовка `X-Dev-User` (имя), telegramId = `dev:<имя>`, роль admin если имя совпало с `DEV_ADMIN_NAME` (или первый вошедший = admin, решить по ходу).
- В `index.ts`: при флаге не звать `setWebhook` и не создавать бота (или создавать заглушку — `createBot` требует токен). Объявления заказа и отправка XLSX должны стать no-op, а не падать: сделать заглушки `OrderAnnouncer`/`DocumentSender`, которые пишут в лог.
- `BOT_TOKEN`/`TELEGRAM_*`/`GEMINI_API_KEY` при флаге не должны быть обязательными в `loadConfig`.

**Мини-апп** — `mini-app/src/telegram.ts`, `apiClient.ts`:
- Если `window.Telegram?.WebApp` нет — не кидать ошибку, а спросить имя через `prompt('Имя')`, положить в localStorage и слать заголовок `X-Dev-User`.

**Тесты:** middleware в dev-режиме пускает по `X-Dev-User` и отдаёт роль; в обычном режиме — по-прежнему 401 без initData.

## 5. Сверка отдельным экраном, потом распределение

Сейчас: кнопка «На сверку» просто меняет статус, чек-лист висит куском на экране управления.

**Надо:**
- Кнопка **«Сверка»** открывает отдельный экран сверки по всему заказу (как в Stitch): по позиции — сколько нужно / сколько привезли, степперы.
- Сохраняется сразу при каждом изменении (эндпоинт `POST /orders/:id/checklist/:itemId/adjust` уже такой) — ушёл и вернулся, видишь свои цифры.
- **После** сверки, если есть недовоз, открывается форма распределения — только по расходящимся позициям (`GET /orders/:id/discrepancies` уже отдаёт только их).

**Файлы:** создать `mini-app/src/admin/ChecklistPage.tsx`; `AdminOrderPage.tsx` (вынести чек-лист, кнопку «На сверку» заменить на «Сверка», распределение оставить как есть).

**Решено:** сверка доступна только при закрытом сборе. Кнопка «Сверка» из статуса `ordering` переводит заказ в `awaiting_validation` (при этом генерируется чек-лист) и сразу открывает экран сверки. Если поспешил — «Вернуть в работу» возвращает в `ordering`, как сейчас. Предупредить об этом в подтверждении: сбор закроется.

### 5.1. Распределение: заранее проставлено «как надо»

Сейчас заготовка пропорциональна заказанному с округлением вниз — в итоге у всех меньше, чем заказывали, и распределять надо всё заново.

**Надо:** каждому сразу проставлено то, что он заказал, и остаётся отметить только разницу.

**Файл:** `server/src/domain/distribution.ts`, функция `proposeSplit` → `proposedDeliveredQty = item.quantity`.

Тогда по позиции с недовозом сумма заготовки больше привезённого, и админ снимает лишнее; при перевозе — меньше, и админ раздаёт лишнее. Валидация в `applyDelivery` («сумма должна совпасть с привезённым») уже это ловит, менять её не нужно — кнопка «Завершить заказ» просто останется заблокированной, пока не сойдётся.

**Фронт** (`AdminOrderPage.tsx`, экран распределения): счётчик показывает знак и глагол вместо «осталось N»:
- сумма больше привезённого → «снять N»;
- меньше → «раздать N»;
- сошлось → «распределено».

Тесты: обновить `distribution.test.ts` (заготовка = заказанному, а не пропорция) и тест экрана в `AdminOrderPage.test.tsx`. Обновить §7.1 спеки — там сейчас написано «пропорционально заказанному, округление вниз».
